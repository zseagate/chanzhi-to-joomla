# 老 CMS 搬家 Joomla 5：一次 1500 篇量级的迁移实战复盘（含 AI 结对细节）

> 背景：某行业协会官网，老系统是某国产 CMS（文章–栏目 1 对多），目标 Joomla 5。全程 AI 编程助手结对，不隐瞒：CSS、模板、批量 SQL 主要是 AI 写的，人负责讲需求、定校验、点头发版。下面是能直接抄作业的部分。

## 0. 先说分工（省流：AI 干体力，人当守门员）

- 人说现象和验收标准：“轮播图和频道行之间要和源站一样 14px”“文件公告里必须出现那篇培训通知”。
- AI 写代码、查源码、定位报错，一轮一轮改。
- **铁律**：AI 产出的每条 SQL、每次文件改动，必须过校验脚本或肉眼抽查才能入库/上线。迁移的脏活，错一次就是线上事故。

## 1. 数据模型先行：1 对多是最大坑

源库关系表长这样（列序 `type,id,category,lang`）：

```
article  1716  17
article  1716  77
```

一篇文章挂两个栏目、共用一个 URL。Joomla 一文一分类，ETL 若只取一个栏目，别的栏目列表就缺文——上线后才被问“为什么那篇文章在这栏看不到”，返工 380 多行。

**抄作业**：
```sql
-- 先统计一文多栏规模，再决定方案
SELECT id, COUNT(*) c FROM eps_relation
WHERE type='article' GROUP BY id HAVING c > 1;
```
方案：主行保留，其余栏目补副本行（换 catid/alias，不写 301）。补行 alias 规范：`c<栏目id>-<源id>`，一眼能溯源。

## 2. 增量追平：源站是活的

迁移周期内源站新发 10 篇、改 6 页、删 2 页。做法：拿到新备份做三路 diff（新增 / 删除 / 内容变更各走各通道），删文只下架不物理删，301 改指上级栏目。核心是一个 60 行的比对脚本，输出形如：

```
新增文章(10): 1708 ... 1717
删除文章(2): 8 流程指南 / 9 秘书处
内容变更文章(6): 1 ... 6（多为重存的空白差异）
```

## 3. 转义：导出—处理—回写链路的魔鬼

命令行 batch 导出的数据**已经转义过**，NULL 显示成字面量 `NULL`。我们连踩三个：

1. 回写又转一次 → `\'` 变 `\\\'`，字符串提前终止，1064；
2. NULL 哨兵用错（`\N` 是 OUTFILE 的格式，CLI 输出的是 `NULL`）→ 日期列 `'NULL'` 被打回；
3. 解析脚本迭代 stdout 字符串，拿到的是**单个字符**不是行（`for line in stdout` 经典翻车，加 `.splitlines()`）。

**抄作业**：铁律两条——解析时整字段 `NULL` 还原真 NULL；回写只加引号不二次转义。先拿一条含引号+换行+空值的记录做往返测试。

## 4. 文件链接的“小尾巴”与无后缀存储

`file.php?f=编号&t=jpg` 后面拖着 `&o=&s=&v=时间戳`，整串去取文件必错；磁盘文件无后缀，靠附件表还原。以及：源站限流（并发 500 页直接封 IP），落地页只给 5 条——**比对以 SQL 为准，线上只抽查，抓取单请求加间隔**。

## 5. 置顶语义：Joomla 藏得很深的那个排序

栏目列表要“只置顶一篇、其余按日期”：菜单排序选 `Featured Articles Order`（`orderby_sec=front`），它的 SQL 是推荐降序、其余日期倒序——正好就是需求本身。但首页文章模块没有这个复合排序，后台做不到，只能写 30 行备用布局把星标文章前置。统一之后：**置顶=点星，去星=恢复**，全站通用。

## 6. 写库流程（每次默念）

1. 全量脚本默认 dry-run，只产出 SQL 文件；
2. 校验：行数、ID 连续、别名唯一、权限树 lft/rgt 成对、asset_id 对应新建 asset、新增区间库内为 0；
3. `--apply`，返回码非 0 立刻查计数——曾出现权限表进了、文章表没进的半截写入，靠区间 DELETE 回滚；
4. curl 抽 URL（状态码+关键字）+ 截图留证。

## 7. 关于 AI 结对的一点实话

- 以前这种活不敢接：不会 CSS、不会模板、不会数据库，只能人工复制粘贴，慢且错得无声无息。
- 这次敢接，是因为每一步都有校验托底：行数对不上、ID 不连续，入库前就被拦。人只做两件事：把现象讲准，把关点好头。
- AI 也会自信地犯错（比如上面 P3 的三连踩有一半是它写的代码里带的），所以第 6 节的流程不是摆设，是保命绳。

---

 **一句话总结**：迁移最大的风险从来不是目标系统的新功能，而是那些“我以为是这样”的想当然——1 对 1 还是 1 对多、NULL 长什么样、排序到底按什么排。先把这些问清楚，剩下的就是体力活，而体力活现在可以交给 AI。

## 8. 开源了，拿去即用

上面提到的脚本已整理成开源项目（MIT）：**https://github.com/zseagate/chanzhi-to-joomla**

里面有：`dump_table`（备份解析）、主 ETL（含试迁/全量/301/Sitemap/工作流关联）、`multichannel_dup`（多栏目补副本）、`refresh_pages`/`rebuild_bodies`（增量）、`shot/gaps/probe/cmp`（截图校验栈），外加这篇复盘的完整版 playbook。配置收敛在一个 `config.py`，适配自己站点主要改栏目映射和菜单。星球里的朋友拿去改改就能用，欢迎 Star 和 PR。
